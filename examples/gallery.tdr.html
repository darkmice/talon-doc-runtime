决策与结论

<d> / <decision> — 带 因/果 的结论卡

用 <because>/<so> 表达前提到结论；s= 控制状态色，v= 是裁决徽章。

当前的「最后写入获胜」会在两人同时拖拽同一图层时丢笔，已收到 12 起投诉。 切换到 CRDT，本地先应用、后台收敛，冲突由数据结构天然消解，不再依赖服务器仲裁。 提案是同一画布同一时刻只允许一人编辑，能彻底避免冲突。 否决：违背「实时协同」的产品定义，把多人体验降级成排队，且锁服务本身会成为新的单点。 弱网用户希望断线后仍能作画，重连再同步。 通过，但限定单画布缓存上限 50MB，并要求重连时给出明确的合并提示，避免静默覆盖。 设计侧希望像 Figma 一样支持任意时间点回放。 暂列为探索项 — 需先评估快照存储成本，下个迭代给结论。

提示框与折叠

<call> / <callout> — 五种 k= 类型

覆盖 note / ok / warn / bad / info，并演示带 t= 标题与不带标题两种形态。

协同光标颜色取自用户头像主色，确保多人时易于区分。 CRDT 合并在 50 人压测下未出现丢笔，端到端延迟 P99 84ms。 离线缓存上限调整后需同步更新移动端，否则两端行为不一致。 SDK 在 Safari 16 下 WebSocket 重连失败，发布前必须修复。 不带标题的 info 提示：本节所有数据来自 5 月预发环境压测。

<c> / <collapse> — 展开与折叠

o 让折叠默认展开；不写则默认收起。

对比过 OT 与 CRDT。OT 实现简单但需要中心服务器做变换；CRDT 客户端复杂但天然支持离线与去中心，最终选 CRDT。

悲观锁、乐观锁 + 版本号、操作日志回放三种方案的详细推演记录，归档备查。

<x> — 行内徽章的全部状态

同一行展示 ok / bad / warn / note / info / active / accent 七种状态。

合并引擎 已上线 离线同步 灰度中 无限回溯 探索 Safari 兼容 阻断 移动端对齐 待跟进 埋点 默认 关键路径 P0

对比

<cmp> / <pro> / <con> — 优势 vs 风险

左列为支持理由，右列为代价与风险。

  • 天然支持离线与去中心化
  • 无需中心服务器做操作变换
  • 合并是确定性的，可重放
  • 客户端内存占用上升约 15%

发现与证据链

<finding t=> / <detail> — 结论 + 展开细节

摘要常驻可见，细节折进 <detail>。

断线超过 30 秒后重连，本地缓存可能覆盖他人改动。

根因：重连后直接以本地序号为准回放，未与服务端做因果比较。修复方案是引入向量时钟，重连先比对再合并，冲突弹出提示。

<evidence t=> / <ei> — 结论 + 支撑要点

顶部是结论，下面逐条列出支撑证据。

属性测试：1 万次随机并发序列，最终状态全部一致。 50 人压测：连续作画 30 分钟，零丢笔。 线上灰度 10% 两周，冲突相关投诉降为 0。
